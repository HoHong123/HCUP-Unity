확인된 반영 사항:

- `DialogueDirector.PlayCatalog()` 가 시작 노드 유효성 검증 후에만 기존 카탈로그를 종료한다.
- `DialogueDirector.SelectChoice()` 가 valid key 검증을 수행한다.

- `StageSlot` 이 `FacingDirection` 에서 분리됐다.

이전 리뷰의 핵심 P1 두 건은 실제로 정리됐다. 이번부터는 문제의 중심이 `Manager/UI/Input` 계층으로 이동했다.

## 구조 평가

현재 구조는 이전보다 분명 좋아졌다.

- `DialogueDirector` 는 그래프 실행만 담당한다.
- `DialogueManager` 는 UI, Input, History, Audio를 묶는 오케스트레이터다.
- `CharacterStageDirector` / `CharacterPortraitController` 분리는 유지되고 있다.
- `DialogueTagRegistry` 로 런타임/에디터 규칙 소스가 일원화됐다.

즉, 아키텍처 방향은 맞다. 다만 `DialogueManager` 에 실사용 진입점이 몰리면서, 사용자 입력 계약과 Inspector 계약이 아직 느슨하다.

## 주요 지적사항

### [P1] Play 버튼이 초기 상태에서는 사실상 죽어 있다

위치:

- `HDialogue/Runtime/DialogueManager.cs:273`
- `HDialogue/Runtime/DialogueManager.cs:140`

`_OnUiPlay()` 는 `currentCatalog != null` 일 때만 `PlayCatalog(currentCatalog)` 를 호출한다.  
문제는 `currentCatalog` 가 `PlayCatalog()` 를 한 번이라도 외부에서 호출해야만 채워진다는 점이다.

즉, 씬에서 `targetCatalog` 만 배선하고 UI `Play` 버튼으로 첫 대화를 시작하려는 정상 흐름에서는 아무 일도 일어나지 않는다. 이건 명백한 사용자 플로우 결함이다.

수정 방향:

- `_OnUiPlay()` 는 `PlayDefault()` 를 호출해야 한다.
- `currentCatalog` 는 “현재 재생 중이거나 마지막으로 성공적으로 시작된 카탈로그” 로만 갱신하는 편이 맞다.

### [P1] 입력 계층이 현재 프로젝트 InputSystem 규약과 맞지 않는다

위치:

- `HDialogue/Runtime/Controller/DialogueInputController.cs:39-48`

`DialogueInputController` 는 `Dialogue` 액션맵과 `Advance`, `Skip`, `AutoToggle`, `HistoryToggle` 액션을 하드코딩한다.  
하지만 현재 프로젝트 규약은 `SWUInputAction` / `Architech` 액션맵 기반이다.

이 상태면 코드 품질 문제가 아니라 연결 자체가 안 된다. Inspector 에 별도 전용 액션 애셋을 또 만들지 않는 이상, 현재 프로젝트 표준 입력 자산과 분리된 외딴 시스템이 된다.

수정 방향:

- 프로젝트 공용 InputAction 자산에 맞추어 리매핑하거나,
- HDialogue 전용 액션 자산을 쓰려면 그 사실을 패키지 계약으로 명확히 고정해야 한다.

지금 구현은 둘 다 아니다. 그래서 통합성 점수는 낮다.

### [P2] 선택지 UI가 Director 승인 없이 먼저 닫힌다

위치:

- `HDialogue/Runtime/DialogueManager.cs:300-302`
- `HDialogue/Runtime/Graph/DialogueDirector.cs:135-145`

`DialogueManager._OnUiSelectChoice()` 는 `director.SelectChoice(key)` 호출 직후 무조건 `uiController.HideChoices()` 를 실행한다.  
하지만 `DialogueDirector.SelectChoice()` 는 상태가 `WaitingForChoice` 가 아니거나 key 가 유효하지 않으면 요청을 거절한다.

즉, stale click, 잘못된 외부 호출, 교체/중단 타이밍 레이스가 끼면 Director 는 선택을 받지 않았는데 UI만 먼저 닫힐 수 있다. 이전 리뷰에서 key 검증은 들어갔지만, UI 쪽 승인 계약은 아직 없다.

수정 방향:

- `SelectChoice()` 가 `bool` 성공 여부를 반환하게 하거나,
- 선택지 닫기는 Director 쪽 상태 전이 후 이벤트로 처리하는 편이 안전하다.

### [P2] 필수 참조 검증이 여전히 Assert 계약이 아니라 로그+조용한 실패다

위치:

- `HDialogue/Runtime/DialogueManager.cs:186-199`
- `HDialogue/Runtime/Portrait/CharacterStageDirector.cs:59-64`
- `HDialogue/Runtime/Portrait/CharacterPortraitController.cs:91-97`
- `HDialogue/Runtime/Controller/DialogueHistoryController.cs:61-80`

사용자 규칙상 “사실상 반드시 연결되어야 하는 참조” 는 early-exit 가 아니라 `Assert` 로 다뤄야 한다.  
그런데 핵심 컴포넌트들이 여전히 `HLogger.Error` 후 살아남거나, null-safe 로 흐름을 삼켜 버린다.

이 방식의 문제는 단순하다.

- 에디터에서 배선 실수를 즉시 끊어내지 못한다.
- 런타임에서는 일부 기능만 죽은 반쯤 살아있는 상태가 된다.
- 문제 발견 시점이 늦어진다.

특히 `DialogueManager` 는 owner 성격의 루트 컴포넌트다. 여기서 `director`, `textController`, `uiController` 가 없으면 시스템을 계속 살려둘 이유가 없다.

### [P3] InputActionMap enable/disable 소유권이 지나치게 공격적이다

위치:

- `HDialogue/Runtime/Controller/DialogueInputController.cs:39-52`
- `HDialogue/Runtime/Controller/DialogueInputController.cs:54-63`

`DialogueInputController` 는 `OnEnable()` 에서 액션맵 전체를 `Enable()` 하고, `OnDisable()` 에서 전체를 `Disable()` 한다.  
이 방식은 해당 `InputActionAsset` 이 다른 시스템과 공유될 경우 소유권 충돌을 만든다.

전용 애셋만 쓴다는 계약이면 허용 가능하다. 하지만 현재 코드는 그 전제를 타입이나 구조로 강제하지 않는다.

수정 방향:

- 정말 전용 애셋이면 이름을 더 노골적으로 분리한다.
- 공용 애셋이면 개별 액션 구독만 하고 맵 활성화 소유권은 상위 시스템으로 올려야 한다.

## 장점

- `DialogueDirector` 의 종료 계약은 이전보다 훨씬 명확해졌다.
- `OnChoicePresent(validChoices)` 로 UI-Director 데이터 계약이 정상화됐다.
- `StageSlot` 분리는 개념적으로 옳다. 이전 설계의 혼선을 끊었다.
- `DialogueTagRegistry` 도입은 실제 유지보수 비용을 낮춘다.
- `CharacterPortraitController` 의 Motion 채널 정리는 이전 대비 확실히 안정적이다.

## 구조적 판단

현 상태의 핵심 문제는 “그래프 런타임” 이 아니라 “통합 경계” 다.

- 그래프 실행기 자체는 이전보다 건강하다.
- 대신 사용자가 실제로 누르는 `Play`, 실제 프로젝트가 쓰는 `InputAction`, 실제 Inspector 배선 실패 같은 경계에서 구멍이 남아 있다.

이건 후순위 미관 문제가 아니다. 실제 씬 연결 단계에서 바로 터지는 결함들이다.

## 보안 및 안정성 관점

보안 측면에서 치명적인 외부 입력 취약점은 이번 범위에서 보이지 않았다.  
대신 안정성 측면에서는 다음이 남아 있다.

- UI가 Director 승인보다 먼저 상태를 바꾼다.
- 필수 참조가 Assert 없이 조용히 실패한다.
- 입력 자산 계약이 프로젝트 표준과 불일치한다.

즉, 공격 표면보다는 운영 안정성 리스크가 더 크다.

1. `DialogueManager._OnUiPlay()` 를 `PlayDefault()` 기반으로 교체한다.
2. `DialogueInputController` 를 현재 프로젝트 InputSystem 규약과 맞춘다.
3. 선택지 닫기 계약을 Director 승인 후로 옮긴다.
4. 필수 `SerializeField` 를 `Assert` 기준으로 정리한다.
5. InputActionMap 소유권을 명확히 분리한다.
